# 布置模板

实现阶段每次只输出一个布置。需求 / 设计 / 计划阶段把「改代码」换成「回答或确认这一段」，结构相同。

## 必须包含的五块

```markdown
### 你在哪
阶段 X · 计划任务《……》· 小步《……》

### 这一步做什么
一句话目标 + 为什么现在做它。

### 怎么做
1. 打开哪个文件（没有就说明是否新建、放哪）
2. 写哪种测试或代码（行为、函数名、输入输出，不是完整可交作业实现）
3. 避开什么（不要顺手做下一步、不要改无关文件）

### 完成定义（只有这一个）
- 文件：
- 命令或手工步骤：
- 看到什么才算过：

### 做完怎么回
- 做完了：你这句话只让我开始验收。我读文件并跑上面的定义，我判定通过才进入下一步
- 卡住了：说卡在哪一步、屏幕上是什么
- 代写当前这一步：我只写本步范围；我按完成定义验收通过后才带你走读并进入下一步
```

## 完成定义怎么写

好：`在 backend/src/test/java/.../LoginTest.java 增加 testBlankCodeRejected；运行 mvn -Dtest=LoginTest#testBlankCodeRejected test；看到失败原因是验证码为空被拒绝，而不是编译错误。`

坏：`把登录做完`、`代码写对就行`、`你懂的`。

## 代写当前步时

布置里把「怎么做」改成你正在写的范围声明，写完立刻带读：

- 改了哪些文件
- 关键逻辑为什么这样
- 用户怎么自己再跑一遍验收

教练按完成定义验收通过后才带读并进入下一步，不要求用户复述。未通过就停在这一步。`progress.md` 记 `authored_by: agent`。下一布置第一句写：默认又轮到你写。

## 反馈（验收之后）

通过：先说出教练核对到的证据（读了哪、命令结果是什么），再说做对了什么，再给 **1 个**改进点（可做可不做），不扩 scope，再给下一步布置。用户口头说对了、但本回合没有证据：不算通过。

不通过：引用证据（文件片段或命令输出），只补「还差什么、怎么补」，五块里目标不变。
