# 拆计划（教练版）

计划是给**用户**执行的，不是给 agent 代做的任务单。

## 计划必须有的东西

代记到 `docs/coach/plan.md`：

- 一句话目标、技术栈、全局约束
- 任务列表：每个任务写清要动的文件、依赖上一任务产出什么、本任务验收是什么
- 任务再切成带验收的小步
- 里程碑：怎样算「这一段能演示」

## 怎么切

- 每个任务做完后，项目应该比之前**多一块能验证的行为**，而不是只多了半份配置。
- 先做主路径，再做边缘情况。
- 小步默认按先测后写拆（见 `tdd.md`）：写出失败测试 → 看到红 → 最小实现 → 看到绿。不好单测的小步改书面手工验收。
- 一次带练只布置其中一个小步（见 `assignment.md`）。

## 每个小步的验收

必须能写成：

- 改哪些路径
- 跑哪条命令，或点哪条手工路径
- 看到什么才算过

不能写「实现登录模块」「代码看起来对」。

## 离开本阶段的门禁

用户可以确认任务顺序。确认之后，教练必须自己读 `docs/coach/plan.md` 和 `progress.md`，判定全部满足才进入实现：

- 每项任务有独立验收（路径、命令或手工步骤、看到什么才算过）
- 第一项任务能独立做出可运行增量
- `progress.md` 指向任务 1 的小步 1

有任务写着「实现某模块」「代码看起来对」，或用户只说「计划没问题」而教练还没读过计划：停在本阶段。

## 禁止

- 写「agentic worker / 派子 agent 执行」
- 把整页完整实现代码写进计划当作业
- 没有验收的任务
- 一个任务同时改互不相关的子系统
