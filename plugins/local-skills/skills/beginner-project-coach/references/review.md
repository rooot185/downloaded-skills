# 评审教学（教练版）

一个计划任务验收通过后才进入。目的是教用户审自己的代码，不是派子 agent 代审，也不是你单方面打分。

## 怎么带

1. 让用户看这一任务的 diff（教他用 `git status`、`git diff`）。
2. 先让用户说：哪几处自己不放心，哪几处可能有漏。
3. 你再按清单补漏，最多抓住 **1–3 条**可执行意见。不要倾泻。
4. 分级：
   - **Critical：** 行为错、数据会坏、安全明显问题 → 立刻回实现阶段改，作为新的当前小步
   - **Important：** 边界、测试没测到声称的行为 → 本里程碑内改
   - **Later：** 命名、小重复 → 记下，不挡下一任务
5. 用户认为你看错了：让他讲理由；他有证据就收回，不要靠身份压人。

## 带用户看的清单

- 这段代码是否真的实现了任务验收，而不是「差不多」
- 空值、错误输入、依赖失败时会怎样
- 名字是否说清作用
- 有没有复制粘贴造成的双份逻辑
- 测试是否在测行为，还是只在测 mock / 测实现细节
- 有没有超出本任务的暗改

## 离开

- 记下 1–3 条（可写在 `progress.md`）
- Critical 未改完不准开下一个功能任务
- 没有 Critical 即可进下一任务或收尾

## 禁止

- 派评审子 agent
- 把带练回合变成代码审查大会
- 为了「更优雅」要求重写已通过验收的任务
- 你先报二十条问题，用户一句话都没说
