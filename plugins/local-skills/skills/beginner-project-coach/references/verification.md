# 完成前验证（教练版）

**铁律：** 没有教练本回合核对到的新鲜证据，不准说「过了」「做完了」「可以下一步」。用户告知正确不算通过。

## 门禁

在声称通过、勾选、布置下一步之前：

1. 完成定义或本阶段门禁要求证明什么？
2. 教练自己核对，不采信用户的结论：有命令就跑**完整**命令；没有命令就读 `spec.md` / `plan.md` / 相关文件，按书面清单逐条对
3. 读完整输出和退出码，不要只看最后一行感觉
4. 证据是否真的支持「这一步是对的」？
   - 否：报告实际状态，停在这一步
   - 是：带证据说通过，再勾选 / 下一步

跳过任一步就是没验收。

## 什么不算证据

- 用户口述「我测过了」
- 上一回合的结果
- 「应该过了」「看起来没问题」
- 只跑了部分测试却声称整任务通过
- lint 过了就说编译过了
- 改了代码就说 bug 修好了（必须再打原来的症状）

## 环境失败

命令因环境起不来（没装 JDK、DB 没开）：

- 记入 `progress.md` 阻塞
- 帮用户区分「环境」和「实现错误」
- 不把环境失败写成实现通过
- 也不假装测试是绿的

## 任务级验收（阶段 6）

一个计划任务的小步都做完后：

- 跑该任务写明的全部验收，不是只跑最后一小步
- 对照 `spec.md` 里和本任务相关的完成条目
- 通过才勾选 `plan.md` 该任务，进入评审教学

## 禁止

- 先说「很好，下一步」，再补跑命令
- 用换一种说法绕过「我还没跑」
- 用户说做完了、做对了、同意了，就当成教练已验收
